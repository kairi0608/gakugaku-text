# RLSと所有権

通常のユーザー処理は `lib/supabase/server.ts` のセッション付きクライアントを使います。Service Roleを使うのは管理者専用集計・ロール変更など、明示的な管理処理だけです。

## ポリシー概要

- 教材: `owner_id = auth.uid()` の所有者だけが作成・編集。配布済みバージョンは所属生徒が読み取り可能。
- 学習記録・回答: `user_id = auth.uid()` の本人だけ。教師は自分の課題に紐づく提出のみ読み取り可能。
- キャラクター・画像・背景: 所有者だけ。Storageパスの2階層目が `auth.uid()` と一致する場合だけ操作可能。
- クラス: 教師は自分のクラスだけ。生徒は自分が所属するクラスだけ。
- 課題: 教師は自分のクラスへ作成。生徒は所属クラスの公開済み課題だけ。
- 提出: 生徒は自分の提出だけ。教師は自分の課題への提出だけ。
- プロフィール: 本人と管理者。教師は自分のクラスに所属する生徒の表示情報だけ。

EXPはクライアントから差分値を受け取りません。`hub_finalize_attempt_exp` が完了済みAttemptと正解行を確認し、固定ルールと重複防止キーで付与します。

## 既存データ

003適用前の行には所有者がない場合があります。移行は安全のため任意ユーザーへ自動割当しません。その行はService Roleによる監査対象です。根拠が確認できた行だけ、管理手順で `owner_id` / `user_id` を設定してください。

## Storage

Private bucketは `gakugaku-assets` です。DBには公開URLではなく `storage_path` を保存し、画面表示時に短時間のsigned URLを発行します。
