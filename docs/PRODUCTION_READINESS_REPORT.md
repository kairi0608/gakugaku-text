# Production Readiness 監査レポート

最終確認日: 2026-08-14

## サイト全体監査結果

- Next.js App Router の公開ページ、認証ページ、個人・生徒・教師・管理者ページ、API Route、Supabase RLS、Storage、OpenAI 接続コードを横断確認した。
- 教材生成、画像生成、教材保存、学習回答、採点、EXP 加算、クラス、課題、提出、レビュー、キャラクター成長、背景設定には、UI から API、DB / Storage までの実装経路がある。
- サンプル成功レスポンスを返すだけの API、固定の受理済み状態、主要フローを迂回するスタブは検出されなかった。
- 秘密値をクライアントへ返す処理は検出されなかった。AI / Storage の未設定・失敗時は、サーバーログに詳細を残しつつ画面には安全な日本語エラーと識別コードだけを返す。
- 役割別 RLS 契約は、個人所有、生徒の所属と提出、教師の所有クラスと課題、管理者操作、画像・背景の所有権をテストで確認した。

## 修正内容

### UI / レスポンシブ

- デスクトップのサイドバーとコンテンツ領域、モバイル下部ナビの `position` / `z-index` 競合を解消した。
- デスクトップではサイドバー分だけコンテンツ幅を差し引き、モバイルでは幅 100%・左余白 0 に切り替えるよう整理した。
- 320 / 360 / 390 / 430 / 768 / 1024 / 1280 / 1440px で公開画面を描画し、ページ全体と主要要素に横方向のはみ出しがないことを確認した。

### 認証 / 役割

- Server Component で取得した `role` と `gradeBand` を AppShell の初期値に渡し、個人 UI が一瞬表示される役割フリッカーを防止した。
- 初期アカウント情報がない保護ページでは中立な読込表示を出し、`/api/auth/me` の結果が出るまで誤った役割 UI を描画しない。
- `admin` を上位権限として扱い、個人・生徒・教師の通常ページと関連 API にアクセスできるよう統一した。管理者専用ページは引き続き管理者だけに限定する。
- 管理者ホームと管理者ナビゲーションから、各通常ページへ直接移動できる入口を追加した。
- ログイン時の重複ユーザー取得を削除し、フォーム送信中の無効化と表示を追加した。
- Supabase の `token_hash` を検証する `/auth/confirm` を追加し、PKCE 用 `/auth/callback` と用途を分離した。
- 登録確認メールの推奨テンプレート、Site URL、Redirect URL、初期管理者設定 SQL を `AUTH_SETUP.md` に明記した。

### 運用診断 / 安全性

- `/admin/system` に Auth、Database Migration、Storage、OpenAI、Email の診断を追加した。
- 必須 16 テーブルの存在、`gakugaku-assets` バケットの存在と非公開設定、必要な環境変数の設定有無を管理者だけが確認できる。
- 診断はテーブル内容、ユーザーデータ、API キー、サービスロールキーを表示しない。
- 画像 MIME、容量、寸法の検証エラーを安全に区別し、内部エラーの生文をレスポンスに出さないよう統一した。
- クライアント通信の例外処理、処理中表示、二重送信防止、日本語フォールバックを主要フォームに追加した。

### 設定 / テスト

- 秘密値を含まない `.env.example` を追加した。
- Next.js の出力トレースルートをプロジェクト直下に固定し、親ディレクトリの別 lockfile を誤検出する警告を解消した。
- Production readiness、RLS、主要ワークフローの契約テストを追加した。

## 本番反映に必要な外部設定

1. Vercel に `.env.example` 記載の環境変数を登録する。`.env.example` 自体は公開してよいが、実値は GitHub にコミットしない。
2. Supabase SQL Editor で `supabase/migrations` を番号順に適用する。
3. Supabase Auth の Site URL を本番 URL、Redirect URLs に本番 `/auth/callback` とローカル開発 URL を登録する。
4. Confirm signup メールテンプレートを `AUTH_SETUP.md` の `token_hash` 形式へ変更する。
5. `gakugaku-assets` を private bucket として用意する。診断画面で存在と非公開状態を確認する。
6. 初期管理者は `AUTH_SETUP.md` の確認 SQL、対象メールの UPDATE、再確認 SQL の順で設定する。

- そのため、今回成功したのはコード検査、RLS / ワークフロー契約テスト、公開画面のブラウザ描画、Production build である。
